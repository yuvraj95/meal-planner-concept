# Meal Planner Concept

A frontend-only prototype built to validate UX clarity, trust signals, and core positioning for a healthy meal delivery product — before any backend investment.

Built using **Lovable** (vibe coding / AI-assisted frontend prototyping).

**Live Prototype:** [meal-flow-validator.lovable.app](https://meal-flow-validator.lovable.app)

---

## Problem

Healthy meal delivery apps fail to convert health-conscious users because they rely on vague "healthy" labels, lack nutrition transparency, and overwhelm users with choice. Trust is low, portion clarity is poor, and price value is unclear.

---

## What This Prototype Validates

- Do users trust meal claims when kitchen provenance and audit signals are visible?
- Does price-per-macro as a value metric increase purchase intent?
- Do meal plan presets reduce choice overload for key personas?
- Is the onboarding flow clear and low-friction enough to convert?

## Why Prototype First

Prototypes let me validate assumptions with real users before investing in engineering. The goal is always to answer the most important open questions cheaply — whether that is comprehension, trust, navigation clarity, or feature demand — so the team builds with confidence rather than guesswork.
